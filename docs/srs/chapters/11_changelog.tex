\chapter{Changelog}
\label{ch:changelog}

This changelog follows the Keep a Changelog format~\citep{keepachangelog}.
Versions are listed in reverse chronological order. This chapter tracks the
\emph{document} baseline; library releases carry their own
\code{CHANGELOG.md} in the repository (REQ-94). From the next document
version onward, every entry lists the requirement(s) and design decision(s)
it adds or modifies.

\section*{Document 0.2.10, 2026-08-01, The Dependency Table Is Checked, Not Maintained}

A PATCH revision adding no requirement and withdrawing none, correcting
REQ-83. The table it carries is normative, it was hand-maintained beside
\code{pyproject.toml}, and it had drifted in both directions at once.

\paragraph{Changed (REQ-83, the table is checked against the file).}
Six declared dependencies were absent from it: \code{build},
\code{pyyaml}, \code{scipy}, \code{setuptools}, \code{setuptools-scm}
and \code{uncertainties}. The \code{ruff} row stated the range
\code{>=0.5,<1.0} where \code{pyproject.toml} carries the exact pin
\code{==0.15.22}, so the normative document contradicted the reason
REQ-96 requires that pin: \code{ruff} is declared twice, and a range
lets CI and the local hook run different rule sets. And five rows named
packages declared in no extra at all, so a reader could not tell a
policy from a plan and those rows could not be checked against
anything.

\code{tests/test\_packaging\_metadata.py} now checks the table in both
directions: every declared requirement has a row whose range is that
requirement's specifier character for character, and every row claiming
a declared role names something the file declares. The roles are split
for the second direction to have meaning. A \code{planned} row is a
package this project intends to declare and has not, an \code{external}
row is not a Python package at all, and neither may name something
\code{pyproject.toml} declares, so a row cannot go on sitting in an
uncheckable role once the package becomes real.

The table is CHECKED and not GENERATED, deliberately. Generating it
would lose the role and used-for columns, and those columns are the
reason a dependency policy belongs in a specification rather than in a
lockfile. Checking gives the same protection from drift without
discarding what the table is for.

\paragraph{Changed (REQ-83, the pytest floor rises to 9.0.3).} A
security floor rather than a preference. CVE-2025-71176 is pytest's
insecure temporary-directory handling on UNIX, and its advisory gives
the affected range as \code{< 9.0.3} and the patched range as
\code{9.0.3} alone, with no backport to the 8.x series. The previous
\code{>=8.0,<9.0} therefore did not merely exclude the fix; it pinned
this project to a vulnerable pytest with no remedy inside its own
range. \code{pytest-cov} rises to 7.0 in the same movement, because
5.x predates pytest 9 and the two pins are one decision. Measured in a
clean environment before the change shipped: the suite passes unchanged
on pytest 9.1.1 with pytest-cov 7.1.0 and needs no source change.

\paragraph{Changed (REQ-83, the setuptools floor rises to 77).} Not a
tooling preference: the library's license metadata moved to a PEP 639
SPDX expression, which setuptools understands from 77 onward. A floor
of 68 would have let a conforming build environment install a
setuptools that silently emitted the legacy free-text metadata, which
is the defect that change removed.

\section*{Document 0.2.9, 2026-07-31, The Archive Authenticates What It Carries}

A MINOR revision adding no requirement and withdrawing none, widening
the stable requirements named in the paragraphs below: REQ-103, REQ-70,
REQ-102, REQ-15 and REQ-48. The numeral this sentence used to carry is
deliberately gone. It read TWO when the entry widened four, was
corrected to FOUR in the same round that widened a fifth, and a count
maintained by hand beside the list it describes is a second copy of that
list. Ten findings in \code{BRF-059}
turned out to be one defect wearing ten faces, and naming it is the
whole of this entry: \emph{state that decided how an archive behaves on
reopen was sitting outside the digest that authenticates it}.

\paragraph{Changed (REQ-103, the operating mode enters the scope).} The
critical one. \code{Provenance.mode} decides whether every export is
refused, and it was not hashed. Measured: the same file, the same
\code{itc.open}, one edited JSON string inside the ZIP, and the members
differing were \code{[provenance.json]} alone; the state hash was
byte-identical to the original, the archive reopened as production, and
a \code{to\_json} that had raised \code{DraftModeExportError} was then
allowed with no \code{allow\_draft} anywhere. A draft file became an
official result by an edit that left the guarantee intact, which means
the guarantee was not covering the thing that mattered.

\paragraph{Changed (REQ-103, the spatial coordinate system enters the
scope).} A cartesian and a polar frame carrying identical arrays shared
a digest, and the tag was persisted nowhere, so a polar frame reopened
cartesian. The tag selects the integration element (REQ-28), so this is
two different numbers from one certified identity.

\paragraph{Changed (REQ-103, the encoding becomes canonical).} Fields
were separated by a bare \code{0x1f} and the comment was written as
\code{(comment or "")}, so a MISSING comment and an EMPTY one produced
one digest, and content carrying the separator crossed field
boundaries: \code{("op1\textbackslash x1fx", "y")} and
\code{("op1", "x\textbackslash x1fy")} collided. Framing is now
length-prefixed and absent is a distinct token from empty. The rule
that an unset metadata field contributed nothing is withdrawn with it:
that rule existed only to bound the DD-40 compatibility break, and
framing now does its work.

\paragraph{Changed (REQ-70, the member manifest).} Only the final state
hash and the replay-steps digest were authenticated, so an individual
\code{HistoryEntry.state\_hash} inside a saved archive could be forged
to 64 zeros and the archive still opened. \code{metadata.json} now
names every other member with its SHA-256 as written, verified in both
directions before any member is interpreted.

What this is NOT is stated in the requirement rather than left for a
reader to over-infer: tamper EVIDENCE, not tamper proofing. The archive
carries no secret, so an editor who rewrites a member and recomputes the
manifest still produces a file that opens. What ended is the case where
an edit needed nothing else at all.

\paragraph{Changed (REQ-70, coordinate dtype, and the schema break).}
Coordinates were serialized by \code{tolist()} with no dtype and rebuilt
as float64, so an INTACT archive holding float32 coordinates raised
\code{HashMismatchError} on reopen: the guard was failing files nobody
had touched, which is how a guard loses its authority. The dtype is now
recorded and restored.

The schema is \code{itaca-itc/3} and its two predecessors are REFUSED
by name. This is the part that costs a user something, so the reason is
in the requirement: neither predecessor records a coordinate system, so
a polar frame CANNOT be reconstructed from one, and reading it as
cartesian would be the very defect this revision closes. A defect must
not be the remedy for a defect, so the archive is refused with a
message naming the migration instead of being silently reinterpreted.

\paragraph{Changed (REQ-102, the flag is not the guarantee).} The
requirement asked for the read-only flag and for tests that in-place
mutation raises. Both were satisfied while the guarantee was false:
\code{setflags(write=True)} restored write access directly, and after
that was closed with a read-only view, the owner behind it was still
reachable as \code{values.base} and could still grant itself write
access. Two independent review passes found the second route. REQ-102
now requires that no owner reachable from the array can restore the
flag, and requires the tests that measure it.

\paragraph{The consequence, stated once.} Every state hash in existence
changes. The framing, the mode and the coordinate system land in ONE
migration rather than three, and the schema refusal is what explains
the change to a user rather than leaving them to meet it as an
unexplained mismatch (DD-47).

\paragraph{Changed (REQ-70, a file ITACA writes is a file ITACA
reads).} A CSV produced by \code{to\_csv} was NOT accepted by
\code{itc.load}. The loader took the first non-empty line as the
header, so the provenance preamble REQ-71 requires became it, and the
file ITACA had just exported was refused by ITACA with a message about
field counts. Parsing also split the text on lines before the CSV
reader could see the quoting, so a coordinate exported as
\code{"front\textbackslash nrear"} came back as \code{frontrear}. The
requirement now states the round trip, because a format that cannot be
read back is not an export format.

\paragraph{Changed (REQ-70, split\_by refuses instead of
overwriting).} The filename stem collided for distinct textual
coordinates, and the second slice overwrote the first with no signal:
two runs went in and one file came out, holding data the filename did
not describe. The collision is now detected across all slices before
anything is written.

\paragraph{Changed (REQ-70, the JSON non-finite policy).} Author's
decided call. NaN and both infinities all exported as \code{null},
erasing the distinction between a point never measured and a
computation that diverged. NaN stays \code{null}; the infinities are
strings, which keeps the file strict JSON.

\paragraph{Changed (REQ-70, the combined uncertainty is exported).}
Author's decided call. The export carried the components and not the
combined value the API computes, so a consumer reimplements the rule
and the plausible wrong guess ignores declared correlation. It ships
with the sentence naming its composition, because a number a consumer
cannot interpret is a number they will recompute.

\paragraph{Changed (REQ-15, the manifest is RFC 4180).} It was built
with a plain comma join, so a source path containing a comma corrupted
its own row cardinality. An audit checkpoint that misreports which file
carried which coordinates is worse than no checkpoint.

\paragraph{Changed (REQ-48, the \code{.itceq} is judged when it is
read).} A TOML constant of \code{nan} or \code{inf} passed validation
and made every equation reading it non-finite, and a disallowed
operator such as \code{x // 2} was refused only at application time,
after a load, a processor construction and an explicit
\code{validate()} had all reported the file as fine. Both are refused
at parse time now, the operator check running the SAME converter
\code{compute} runs so the two answers cannot drift apart. Name
resolution stays deferred, which the requirement now says explicitly.

\section*{Document 0.2.8, 2026-07-31, The Engine States Its Scope: One Expression}

A MINOR revision adding no requirement and withdrawing none, and
narrowing SIX stable ones to what the implementation can deliver. Every
change closes a silence that a user could only discover by getting a
wrong number, which is the drift this document is monitored for.

\paragraph{Changed (REQ-41, the scope of symbolic propagation).} The
requirement described GUM clause-5 propagation by chain rule on the AST
and said nothing about where the guarantee stops. It stops at the
expression boundary. The chain rule sees one operator tree, so a
variable appearing twice in one \code{compute} cancels exactly; but a
derived variable is STORED as values plus an uncertainty, with no record
of the inputs that produced it, so the next operation reading two such
variables treated them as independent when they are not.

The error goes both ways and both were measured on \code{dde261c}. From
\code{p = 3*x} then \code{q = 2*x} then \code{r = p - q},
\code{u(r) = 0.3606} where the correct value is \code{0.1}: a 3.6x
OVERSTATEMENT. From \code{y = 2*x} then \code{z = y - 2*x},
\code{u(z) = 0.2828} where zero is exact. Two sequential
\code{translate\_moments} gave \code{1.414} against a correct
\code{2.0}, a 29\% UNDERSTATEMENT, and \code{interpolate} followed by
\code{average} understated the random component by 21\%. The identical
arithmetic written as ONE expression was correct in every case, which is
what makes the interim answer a refusal with a way forward rather than a
removed capability.

REQ-41 now states the one-expression scope and the refusal
(\code{UncertaintyLineageError}). The refusal names the equivalent
single expression, built by substituting each derived variable's own
recorded equation, so the user is handed a line to paste rather than an
explanation of covariance. It covers \code{compute} where two
uncertainty carriers share an origin, \code{translate\_moments} stacked
on an earlier transfer (REQ-100), and a RANDOM-component reduction over
a dimension an earlier \code{interpolate} produced (REQ-98, REQ-99); the
systematic reduction rule is untouched, since the absolute weighted sum
already assumes full correlation and stays valid when points become
more correlated. A pair declared with \code{set\_correlation} is
propagated rather than refused.

Ancestry is read from History, which REQ-18 already guarantees, so no
frame carries new state and a frame written before this version is
analyzable by it. The detector is conservative by construction: it
over-approximates and may refuse a composition that would have been
fine, because a false refusal is an error message and a missed one is a
wrong number in a report.

Lineage with SENSITIVITIES, which would let the engine propagate these
compositions instead of refusing them, is v0.3.0 work and is the
boundary this revision deliberately does not cross. Author decision
SEAT-UNC, 2026-07-31; evidence in BRF-059.

\paragraph{Changed (REQ-36, non-differentiable POINTS, not only
functions).} The guard refused a NumPy function with no sound
derivative. It said nothing about an operator that has a derivative
almost everywhere and none at a particular point. \code{abs} is that
case: \code{np.sign(0)} is \code{0}, so \code{u(|x|)} at \code{x = 0}
came back as an exact ZERO, asserting total certainty at the one point
where \code{d|a|/da} does not exist, its one-sided limits being $-1$ and
$+1$. Measured \code{u(y) = [0., 0.1, 0.1]} over \code{x = [0, 3, -3]}
with \code{u(x) = 0.1}: the same call is right at two points and
indefensible at the third. The dev-only oracle (DD-25) returns
\code{0.1} there, and two careful implementations disagreeing at exactly
one point is what a non-differentiable point looks like from outside.

Such a point now raises \code{UncertaintyCompatibilityError}, the class
that already covers this family. The rule is narrow on purpose and
applies where a partial is silently WRONG, not merely infinite:
\code{sqrt} and \code{log} at zero return an infinite partial, and an
infinity in a result is not something a reader mistakes for a
measurement.

\paragraph{Changed (REQ-98, what the normative table is a claim ABOUT).}
Table~\ref{tab:unc-ops} states, row by row, how each operation carries
the UncFrame, and every row was and remains correct. What it never said
is what it is a claim about. Each row describes the operation acting on
inputs whose correlation is either independent or DECLARED; none of them
is a statement about composition, because the frame carries no record of
the correlation an operation INDUCES. Read as licensing compositions,
the table contradicted the behavior this revision installs. The preamble
now says so, and points at REQ-41. No row changed.

\paragraph{Changed (REQ-99, the random reduction's independence
assumption).} The $1/\sqrt{N}$ gain is the root sum of squares, which is
the propagation rule for INDEPENDENT points. After \code{interpolate}
each point along that dimension is a linear combination of the same
source points, so the assumption fails: measured
\code{u = 0.5590169944} where \code{0.7071067812} is correct, 21\% low,
with both routes computing the identical function $0.5 Y_0 + 0.5 Y_1$ so
the gap isolates covariance loss and not the reduction rule.
\code{average} and \code{integrate} now refuse that case.

The asymmetry is the part worth stating, because it is a real property
and not an artifact of where the check sits. The SYSTEMATIC rule is the
absolute weighted sum, which already assumes FULL correlation across
points, and an assumption of full correlation stays valid when
interpolation makes points more correlated. So a systematic-only frame
reduces exactly as before, and only the random half is refused.

\paragraph{Changed (REQ-100, one transfer per frame while uncertainty is
present).} The rigid transfer makes $\mathbf{M}'$ a linear function of
$\mathbf{F}$, so the two groups are correlated afterwards however
independent they were before, and that INDUCED correlation has nowhere
to live: a declared matrix holds what the USER declared, not what an
operation created. A second transfer therefore read them as independent
and understated, measured 1.414 against a correct 2.0, 29\% low. A
transfer applied to a frame an earlier transfer already moved now
raises when any channel carries uncertainty, naming the single
equivalent call from the original reference point. With no uncertainty
declared there is nothing to lose and repeated transfers compose
exactly.

Worth recording beside it, with the qualification review round three
supplied. \code{db.rotate} faces the same situation and DOES record
what it induces, writing an ordinary declared pair between the rotated
components, so a later \code{compute} over them propagates correctly
and is not refused. But it does that only where the coefficient
resolves to ONE scalar across the grid: on a two-condition sweep, the
ordinary REQ-101 case, it records \code{correlation\_not\_stored}
and drops the pair rather than inventing a number, and this revision's
detector is then what stops the understatement. So the asymmetry is
real and narrower than it first appears: \code{translate\_moments}
never stores the induced pair, \code{rotate} stores it when it is
representable. Whether \code{translate\_moments} should do likewise,
and what either should do where the coefficient is not representable,
is OQ-51.

\paragraph{Changed (REQ-24, the record concat cannot keep).}
\code{itc.concat} builds the result from its FIRST input, so that
input's History is asserted over every input's rows. Measured both
directions: a derivation present only in a later input is DISCARDED, and
\code{compute("r = p - q")} on the joined frame returned
\code{u = 0.3606} where \code{0.1} is correct on those rows; a
derivation present only in the FIRST input is OVER-asserted, and the
refusal then offered \code{z = (2*x) - 2*x} as already correct, which
returns \code{[0, 0]} where the truth is \code{[0, 97]}.

The test is AGREEMENT across the inputs rather than a scan of the later
ones, because both directions are wrong in the same way. A variable
derived identically everywhere is described correctly by any input's
record, so processing several runs the same way and concatenating them
is unaffected; a disagreement, an absence in some inputs, or an input
whose record cannot be read at all is refused, naming the variable or
the operation. Variables carrying no uncertainty are not considered,
having no covariance to lose.

This was found five ways across three review rounds, each fix reopening
the problem from a different side, which is recorded here because the
shape of the mistake is more instructive than the fix: a rule about a
merge cannot be enforced by inspecting one side of it.

\section*{Document 0.2.7, 2026-07-30, Two Requirements Catch Up With Two Fixes}

A PATCH revision adding no requirement and withdrawing none. Both changes
are clarifications in the strict sense: the requirement was SILENT, the
library's behavior was fixed, and the text now says what the fix decided.
An unwritten rule is the drift this document is monitored for, so the
silence is closed in the same change rather than registered.

\paragraph{Changed (REQ-25, minimum source cardinality).} The requirement
enumerated four interpolation methods and said nothing about how many
source points each needs. \code{"linear"} and \code{"cubic"} interpolate
BETWEEN samples, so at one point the segment lookup collapsed to a
zero-width segment and the weight divided by zero: measured \code{y =
[inf]} under a bare \code{RuntimeWarning} for both methods, where a
two-point control through the identical call returned a finite value
with no warning. REQ-25 now requires at least two points for those two
methods and a refusal before any kernel runs.

The scope of the refusal is the part worth stating. \code{"nearest"}
copies the sample and \code{"polyfit"} with \code{deg=0} fits a
constant, and both are defined at one point; refusing all four would
have removed two working operations to fix two broken ones. A previously
returning call now raises, which is a behavior change, and it is one
that replaces an infinity a caller could carry a long way.

\paragraph{Changed (REQ-35, what \code{fill=None} retains, and where the
equation is evaluated).} Two additions, both closing a silence.

The \code{fill=None} bullet governed the VALUE alone, and the
implementation retained the value and erased the uncertainty: measured,
\code{x = [100., 4.]} with \code{u(x) = [10., 0.4]} came back as
\code{x = [100., 2.]} with \code{u(x) = [nan, 0.2]}, so a surviving
number was paired with an uncertainty that is not a number. The
requirement now says both halves of an untouched point's state are
retained together, and says explicitly that the other two fill modes do
NOT retain, because they WRITE the point and the uncertainty of a
replaced value does not describe its replacement. The existing sentence
that uncertainty is propagated only for filtered-in points is unchanged
in force: retention is not propagation.

The requirement also said the equation is evaluated only where the
condition holds, and the implementation evaluated everywhere and masked
the result. On a domain violation that was visible: measured, \code{y =
sqrt(v)} over \code{v = [-1, 1]} with \code{where="v >= 0"} emitted two
\code{RuntimeWarning}s with an uncertainty carrier and one without, for
a cell that never reached the output. The code now matches the sentence,
and the requirement states BOTH exemptions rather than leaving either to
be discovered. An expression containing an \code{np.*} call is still
evaluated over the whole grid, because a reduction reads cells other
than its own and confining such a tree would change the value of the
reduction itself; the test is conservative and refuses any tree carrying
such a call, elementwise or not. And under \code{debug=True} the REQ-34
sample evaluation stays on the whole grid, so that report shows the
frame's own data rather than the mask.

The second exemption is one this revision's own lane created and then
had to write down: reporting through the mask printed NaN for every
variable whenever the sampled grid point fell outside the condition. It
was found by a review pass over the commit that closed the review, run
because an unreviewed change to this document is worse than an
unreviewed change to code, and the first draft of this section counted
the exemptions as one.

\paragraph{Not changed, deliberately (REQ-39).} A third fix in the same
lane refused a relative uncertainty specification that resolves against
non-finite data. It worked and it was REVERTED, because REQ-39 states
that scope in its own normative text: the finiteness rule is scoped to
the DECLARED magnitude, the structural home of the wider check is the
UncFrame, and it is blocked on OQ-40. Amending REQ-39 to admit the fix
would have settled the boundary that entry parks on the numerical
analyst. Recorded here because two attempts at that fix have now been
reverted for two different reasons, and the order is the thing a third
lane needs: REQ-39 moves first, or nothing moves.

\section*{Document 0.2.6, 2026-07-30, Release Review: Three Claims Withdrawn}

A PATCH revision withdrawing three claims this document made and could not
keep. No requirement is added and none is withdrawn. Found by the v0.2.0
RELEASE review, which is the first pass over the whole M1 surface at once,
and all three are of one kind: text that was correct when written and became
false without anyone editing it.

\paragraph{Changed (REQ-70, an absent method promised as an export
format).} REQ-70's export list carried
\code{db.export\_provenance(path, format="prov-json")} with no qualifier,
and that symbol exists nowhere in the package. It is now marked an M2
deliverable and NOT IMPLEMENTED.

This is the chapter~6 residual of \code{ITACA-012}, and the reason it
survived is worth more than the fix. When that finding was first closed,
chapter~8 was corrected and a guard was written to keep the claim and the
symbol from drifting apart again. The guard read chapter~8. So the finding
was closed, a mechanism was installed, and the same claim went on standing
in a STABLE requirement box one chapter over, which is the shape this
repository names as measuring the mention instead of the carrier. The guard
now walks every chapter.

\paragraph{Changed (Chapter~\ref{ch:standards}, what the docstring
checker actually enforces).} The chapter said SECTION COMPLETENESS on the
declared public surface is enforced by
\code{tests/test\_docstring\_sections.py}. That checker requires
\emph{Parameters} and \emph{Returns}. REQ-79 names four sections, so
\emph{Raises} and \emph{Examples} completeness is machine-checked by
nothing, and the release review found four public methods whose
\emph{Raises} sections omit refusals the library actually performs. The
sentence now says which two are enforced.

Note the direction: the paragraph being corrected is itself the correction
made for \code{ITACA-016}, where an earlier revision had claimed LINTING
enforced the sections. That correction overclaimed in the same direction as
the error it replaced, which is why this entry states the mechanism's scope
rather than its existence.

\paragraph{Changed (Chapter~\ref{ch:roadmap}, a module that is not
there).} The v0.2.0 deliverables table named
\code{ops/fitmodel.py}, \code{ops/fitvalue.py}. There is no
\code{ops/fitvalue.py}: \code{fitvalue} is defined beside
\code{fitmodel}. The second path is removed.

\paragraph{Changed (Chapter~\ref{ch:introduction}, the same claim
without the symbol).} The standards list said W3C PROV-DM is a conceptual
reference ``with native PROV-N and PROV-JSON export support in \itc{}'',
present tense, for a capability that exists nowhere. It now says the export
is planned as an M2 deliverable and NOT IMPLEMENTED in v0.2.0.

Worth the paragraph because of HOW it survived. The guard widened above walks
every chapter, and it keys on the literal \code{export\_provenance}. This
sentence claims the same capability without naming the method, so the widened
guard cannot see it either. A guard keyed on a symbol catches a claim that
names the symbol; the class is claims about capability, and no mechanism here
covers that class. Recorded rather than solved.

\section*{Document 0.2.5, 2026-07-30, The Application Moment, Corrected}

A PATCH revision correcting 0.2.4 below, which was written the same day and
in the same unpushed lane. It is a separate entry rather than an edit to
that one, because Chapter~1's rule that every change increments the document
version does not carve out an unpublished revision, and rewriting a
revision entry to say something it did not say is the thing the revision
history exists to prevent. That both entries describe one amendment's two
attempts is a cost of the rule as written, and whether an unpublished
revision may instead be amended in place is part of what
\code{ITC-20260730-0165} asks.

\paragraph{Changed (Section~\ref{sec:itceq}; bears on REQ-41, REQ-45,
REQ-99).} 0.2.4 stated the rule as ONE question, keyed on what the file
produces. Review found that wrong in the mirror direction before release: a
name the VarFrame carries and a \code{[corrections]} line rewrites had its
declaration withheld from the \code{[equations]} lines that READ it, so a
quantity derived from it propagated from the frame's own value. Measured,
with \code{CL = 0.01} declared, \code{CD = "CL * 2"} and a correction
\code{CL = "CL * 1.02"} against a frame carrying a stale
\code{u(CL) = 99}: \code{u(CD)} shipped as \code{198.0} where \code{0.02}
is correct, in a frame that simultaneously reported \code{u(CL) = 0.01}.

The rule is now TWO independent questions, and a name may answer yes to
both, in which case the declaration is applied twice. Neither
single-question form is correct, because a name can be both read and
written.

\paragraph{Changed (Section~\ref{sec:itceq}, the component a declaration
speaks for).} 0.2.4 said no uncertainty the frame arrived with is ever read
for a declared name. That is true of the SYSTEMATIC component and false of
the random one: a declaration is assigned as the systematic component, so an
arriving random component is kept and propagates untouched. Measured on the
file above with \code{u\_random(CL) = 99.0}: \code{u\_random(CD) = 198.0}.
The sentence is qualified, and whether an \code{.itceq} file should be able
to speak for both components is OQ-45.

\paragraph{Added (two open questions cited from the section).} The overlap
the two-question rule introduces has two consequences the section now names
rather than deciding: a name written more than once takes the declaration
after the FIRST write, so a later line propagates over it (OQ-43); and a
RELATIVE declaration on a name assigned twice resolves twice, so one
declaration yields two numbers and a line evaluated between them propagates
from the first (OQ-44). Measured for OQ-44: \code{CL = "10\%"} with

\section*{Document 0.2.4, 2026-07-30, When a Declared Uncertainty Applies}

A PATCH revision by chapter~9's rule: it adds no requirement and withdraws
none, and states in Chapter~\ref{ch:datamodel} a behavior the document had
left unspecified. Whether stating a previously unstated rule is a
clarification or an addition is the standing question of
\code{ITC-20260730-0165} and is the author's to settle; classified PATCH
here for consistency with the 0.2.3 entry below, which recorded a shipped
refusal the same way.

\paragraph{Changed (Section~\ref{sec:itceq}; bears on REQ-41, REQ-45,
REQ-99).} SUPERSEDED BY 0.2.5 ABOVE, whose entry carries the corrected
rule; what follows is what this revision said, kept unedited.

The section rules now state WHEN a declared uncertainty is applied:
before the first equation for a name the file does not produce, and
immediately after the writing equation for a name it does. The rule keys
on what the file produces and never on what the VarFrame carried on the
way in.

The document had said only that the values are absolute or relative and
per-variable, so the moment was unspecified and the implementation had
adopted a single-question rule: it sorted by whether the incoming frame
already carried the name. A written name the frame carried was therefore
assigned before the loop and then overwritten by its own equation's
propagation. With \code{[uncertainties] y = 5.0} alone, the declaration was
lost and the frame shipped no uncertainty at all; with \code{x = 1.0}
beside it, the same file shipped \code{u(y) = 2.0}, which is what
\code{u(x) = 1.0} propagates to through \code{y = "2*x"}, where the file
declares \code{5.0}. A relative declaration such as \code{"10\%"} on a
carried target was lost the same way, since the value the equation
overwrote took the declaration with it.

The wrong-value branch is why this is stated in the specification and not
only fixed in code. A lost declaration is a visible gap. A different,
finite, plausible uncertainty, chosen by whether the input frame happened
to carry a column, is a number a reader has no reason to question, which is
this library's worst failure mode
(\code{R4-ITA-003}, \code{REV-004}, \code{ITC-20260730-0105}).

Stating the rule as one question was itself wrong in the mirror direction,
found by review before release and recorded here because the specification
text is what the mirror case turns on: a carried name that
\code{[corrections]} rewrites, read by an \code{[equations]} line in
between, had its declaration withheld from that line, so a derived quantity
propagated from the frame's own value instead. A name written more than
once remains open as OQ-43, cited from the section itself.
